- kitty-claude: handle C-d (and other ungraceful window closes) gracefully — see state.md.
- M-, (`--attention` → `jump_to_attention`) jumps to windows that are still working rather than ones waiting for input — the attention/idle window state looks wrong (stale or mislabelled entries). Use `:log <note>` to capture a `LOG-MARKER` snapshot (current window + attention/idle maps + window list) when it misfires, then fix the marking logic from that evidence.
- Switch from tmux to Zellij. tmux `display-popup` is client-relative, not window-relative — there is no way to render a permission popup on a specific window without `select-window`-switching the client's view. Zellij supports floating panes anchored to a tab, which is what we actually need for MCP permission prompts.
- Remote `:ssh` — bridge colon commands across the ssh link. Commands are labelled `local_only` (default) vs forwardable (`REMOTE_OK_COMMANDS`, currently just `:cd`); build the forwarder that ships a REMOTE_OK command to `clauthing --profile <origin>` on the far side. Only safe for commands whose state lives entirely on the remote.
- Remote `:ssh` — tmux-in-tmux keybinding capture: the outer (local) tmux swallows `M-\;`, `M-n`, etc. before they reach a remote clauthing session, so colon-command keybindings don't work in an `ssh:` tab. Needs a prefix or key-passthrough scheme.
- Remote `:ssh` version-sync gotcha: the bootstrap trusts the PyPI version string, but same version ≠ same code (unreleased working-tree changes over a released tag lack new flags, e.g. `--new-claude` was missing on the remote's 1.1.1). Consider pinning to a released version or a source/commit hash for dev use.
